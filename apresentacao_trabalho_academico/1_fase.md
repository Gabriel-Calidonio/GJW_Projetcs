PROJETO INTEGRADOR (PI)

Aplicar conceitos aprendidos na disciplina de Programação Web.

Integrar conhecimentos de design de interface, programação web e
gerenciamento de projetos.

Trabalhar em equipe para simular um ambiente de desenvolvimento real.

Definição da Arquitetura:

Utilize um banco de dados relacional como MySQL ou PostgreSQL;

Desenvolver a aplicação utilizando Java e Spring Boot;

Organizar o projeto utilizando uma arquitetura em camadas (MVC),
separando as responsabilidades da aplicação, preferencialmente em:
Controller: responsável pelos endpoints e pela comunicação da API;
Service: responsável pelas regras de negócio;
Repository: responsável pelo acesso e persistência dos dados;
Model/Entity: responsável pela representação das entidades da aplicação;

Criação de uma APIRest:
Desenvolver uma API com funcionalidades para realizar operações CRUD (Create, Read,
Update e Delete) em um cenário ou tabela específico.

Implementar a comunicação entre a aplicação e os clientes por meio de uma API REST,
utilizando adequadamente os métodos HTTP (GET, POST, PUT, PATCH e DELETE);

Além disso, Desenvolva funcionalidades para permitir que os usuários se registrem e façam
login no sistema. - Isso fica por fora do do CRUD

Criar um documento de especificação de API com Swagger, facilitando o entendimento e o
teste das rotas. Ferramentas como Postman ou Insomnia podem ser utilizadas para esta
tarefa.

Sobre o CRUD:
Desenvolver uma API com funcionalidades para realizar operações CRUD (Create, Read,
Update e Delete) em um cenário ou tabela específico.

A API deverá disponibilizar, no mínimo, funcionalidades para:
Cadastrar um novo registro;
Consultar todos os registros;
Consultar um registro específico por seu identificador;
Atualizar um registro existente;
Excluir um registro.
Autenticação e Usuários:
A aplicação também deverá contemplar funcionalidades relacionadas ao gerenciamento de
usuários, incluindo:
Cadastro de usuários;
Autenticação por meio de login;
Armazenamento seguro das credenciais dos usuários;
Proteção dos endpoints que necessitem de autenticação;
Aplicação de boas práticas básicas de segurança.

Boas práticas:
Organização e padronização do código;
Separação de responsabilidades;
Validação dos dados recebidos pela API;
Tratamento adequado de erros e exceções;
Utilização adequada dos códigos de status HTTP;
Segurança das informações e das credenciais dos usuários;
Persistência e integridade dos dados armazenados no banco de dados.
Trabalho colaborativo e Versionamento:
Utilizar o Git como sistema de controle de versão;
Manter o código-fonte do projeto em um repositório remoto, preferencialmente no GitHub;
Garantir que todos os integrantes do grupo participem efetivamente do desenvolvimento;
Realizar commits individuais e frequentes, permitindo identificar a contribuição de cada
integrante;
Utilizar mensagens de commit claras e relacionadas às alterações realizadas;
Utilizar branches para organização do desenvolvimento de novas funcionalidades, quando
aplicável;
