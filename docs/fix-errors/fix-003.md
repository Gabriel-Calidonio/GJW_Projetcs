# Fix-003

## Problema
Ao clicar em "Concluir e Iniciar Sistema" no final do Setup Wizard, o sistema retornava o erro:
`Erro ao finalizar: .env (Permission denied)`

Mesmo o usuário executando `chmod 777 .env` no host (`~/Docker2/Tgos`), o erro persistia.

---

### Causa Raiz
1. **Isolamento de Contêiner**: O comando `chmod 777 .env` foi executado no host, porém o contêiner Docker (`tgos_app`) possui seu próprio sistema de arquivos isolado.
2. **Permissão na pasta `/app` do Contêiner**:
   - No `Dockerfile`, o diretório de trabalho `WORKDIR /app` pertencia a `root:root` com permissão `755` (`drwxr-xr-x`).
   - A aplicação executa como usuário sem privilégios `USER appuser`.
   - Quando o `SetupService.java` tentava criar o arquivo `.env` via `new FileWriter(new File(".env"))`, o usuário `appuser` não tinha permissão de escrita no diretório `/app`.

---

### Solução Aplicada
1. **No contêiner em execução**:
   Ajustada a propriedade do diretório `/app` para o usuário `appuser`:
   ```bash
   docker exec -u 0 tgos_app chown -R appuser:appgroup /app
   ```
2. **No `Dockerfile` (correção permanente para futuros builds)**:
   Adicionada a instrução de permissão antes de definir `USER appuser`:
   ```dockerfile
   COPY --from=build --chown=appuser:appgroup /app/target/*.jar app.jar
   RUN chown -R appuser:appgroup /app
   USER appuser
   ```
EOF`

O problema está **resolvido**! Pode tentar clicar em **"Concluir e Iniciar Sistema"** novamente.

---

### Por que o `chmod 777 .env` no host não funcionou?

1. **Isolamento do Contêiner**: Quando você executou `chmod 777 .env` no terminal da máquina host (`~/Docker2/Tgos`), essa alteração ocorreu apenas no seu computador local. O contêiner Docker (`tgos_app`) possui seu próprio sistema de arquivos isolado.
2. **Permissões dentro do Contêiner**:
   - No [Dockerfile](file:///home/wattrelos/Docker2/Dockerfile), a pasta de trabalho `/app` foi criada pelo usuário `root` (com permissão `755`).
   - Porém, a aplicação Java executa sob o usuário seguro `USER appuser`.
   - Quando o `SetupService` tentava criar o arquivo `.env` dentro de `/app`, o usuário `appuser` não tinha permissão de escrita nessa pasta.

---

### O que foi corrigido:

1. **No contêiner em execução (efeito imediato)**:
   Ajustei a permissão da pasta `/app` diretamente dentro do contêiner para o `appuser`:
   ```bash
   docker exec -u 0 tgos_app chown -R appuser:appgroup /app
   ```
   *(Já testado com sucesso a criação e escrita do `.env` como `appuser`)*.

2. **No [Dockerfile](file:///home/wattrelos/Docker2/Dockerfile#L23-L33) (permanente para futuros builds)**:
   Adicionada a instrução de permissão antes de ativar o `USER appuser`:
   ```dockerfile
   COPY --from=build --chown=appuser:appgroup /app/target/*.jar app.jar
   RUN chown -R appuser:appgroup /app
   USER appuser
   ```

3. Registrado o relatório em [docs/fix-errors/fix-003.md](file:///home/wattrelos/Docker2/docs/fix-errors/fix-003.md).
