# Analise e Solução de Problemas com Java 21 e rota administrativa

### 1. Como fazer o projeto reconhecer o Java 21 sem desinstalar o Java 17

O Java 17 e o Java 21 podem coexistir normalmente no Windows. Para que o projeto use o Java 21 sem afetar o restante do sistema:

1. **Configuração direta no projeto (VS Code / Antigravity):**
   O arquivo [`.vscode/settings.json`](/.vscode/settings.json) já foi atualizado para apontar para a pasta raiz da sua JDK 21:
   ```json
   {
       "java.debug.settings.onBuildFailureProceed": true,
       "java.compile.nullAnalysis.mode": "disabled",
       "java.jdt.ls.java.home": "C:\\Program Files\\Eclipse Adoptium\\jdk-21.0.13.9-hotspot",
       "java.configuration.runtimes": [
           {
               "name": "JavaSE-21",
               "path": "C:\\Program Files\\Eclipse Adoptium\\jdk-21.0.13.9-hotspot",
               "default": true
           }
       ]
   }
   ```
   > [!IMPORTANT]
   > Observe que o caminho deve ser a **pasta raiz do JDK** (`jdk-21.0.13.9-hotspot`), e **não** a subpasta `\bin`.

2. **Se for rodar via Terminal (PowerShell ou CMD):**
   Para rodar com o Maven Wrapper sem alterar as variáveis globais do Windows:
   - **PowerShell:**
     ```powershell
     $env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21.0.13.9-hotspot"
     $env:Path = "$env:JAVA_HOME\bin;" + $env:Path
     .\mvnw.cmd spring-boot:run
     ```
   - **CMD (Prompt de Comando):**
     ```cmd
     set JAVA_HOME=C:\Program Files\Eclipse Adoptium\jdk-21.0.13.9-hotspot
     set PATH=%JAVA_HOME%\bin;%PATH%
     mvnw.cmd spring-boot:run
     ```

### 2. Por que apareceu o erro `404 - Recurso Não Encontrado` para `/adm_736d06afb6ba`?

#### Causa Raiz
1. O processo do servidor Spring Boot foi iniciado **antes** da execução do Setup Wizard (quando o arquivo [`.env`](/.env) ainda não existia).
2. Durante o Setup Wizard, o arquivo [`.env`](/.env) foi criado com sucesso com a rota administrativa gerada:
   ```properties
   ADMIN_ROUTE_PREFIX=adm_736d06afb6ba
   ```
3. O Spring MVC compila a tabela de rotas dos `@Controller` (como `AdminDashboardController` e `LoginController`) **no momento da inicialização** do servidor. Ele não reconstrói dinamicamente os `@GetMapping` em tempo de execução enquanto a JVM estiver ativa.
4. Por essa razão, a aplicação que ainda estava rodando na memória não conhecia a URL `/adm_736d06afb6ba`. Ao receber a requisição, o Spring Boot presumiu que se tratava de um arquivo estático (CSS, JS, imagem) e disparou `NoResourceFoundException`, acionando o tratamento em [`GlobalExceptionHandler`](/src/main/java/com/gwj/controller/GlobalExceptionHandler.java).

---

### Como resolver agora

Basta **reiniciar o servidor Spring Boot**:

1. **Pare o processo atual da aplicação** (interrompa o terminal ou clique no botão de Stop/Reiniciar no VS Code).
2. **Inicie o servidor novamente** (pelo botão *Run/Debug* do VS Code ou com `.\mvnw.cmd spring-boot:run`).
3. Ao subir, o método `main` em [`StartApplication.java`](/src/main/java/com/gwj/StartApplication.java#L10-L15) executará `AppConfig.loadEnv()`, lerá o [`.env`](/.env) e registrará as rotas administrativas em:
   - **Login Administrativo:** `http://localhost:8089/adm_736d06afb6ba/login`
   - **Painel Dashboard:** `http://localhost:8089/adm_736d06afb6ba`
