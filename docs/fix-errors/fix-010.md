# Fixa erro redirect https://agsonhos.com.br/ app-vps

## Redirecionamento para a aplcação principal.
> Você pode resolver isso diretamente no Nginx usando proxy_redirect e o módulo sub_filter. O problema acontece porque a sua aplicação na porta 8089 gera redirecionamentos ou links internos apontando apenas para https://agsonhos.com.br (sem :2096), fazendo o navegador cair na porta padrão 443 onde está a aplicação principal.

## Como ajustar o seu arquivo Nginx

Adicione as diretivas de reescrita de redirecionamento e de conteúdo HTML no seu bloco location /:
```nginx
server {
    listen 2096 ssl;
    listen [::]:2096 ssl;
    server_name agsonhos.com.br;

    # Mesmo certificado SSL do Forgejo
    ssl_certificate /etc/letsencrypt/live/agsonhos.com.br/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/agsonhos.com.br/privkey.pem;

    # Tamanho máximo de upload
    client_max_body_size 10M;

    location / {
        # Porta interna onde a sua aplicação está escutando
        proxy_pass http://127.0.0.1:8089;
        proxy_http_version 1.1;

        # Cabeçalhos para a aplicação saber a porta e o protocolo reais
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Host $http_host;
        proxy_set_header X-Forwarded-Port $server_port;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 1. Corrige redirecionamentos HTTP (301/302) enviados pelo backend sem a porta
        proxy_redirect http://agsonhos.com.br https://agsonhos.com.br;
        proxy_redirect https://agsonhos.com.br https://agsonhos.com.br;
        proxy_redirect http://127.0.0 https://agsonhos.com.br;

        # 2. Reescreve links absolutos dentro do HTML/JS caso o app os gere fixos
        proxy_set_header Accept-Encoding "";
        sub_filter 'https://agsonhos.com.br' 'https://agsonhos.com.br';
        sub_filter 'http://agsonhos.com.br' 'https://agsonhos.com.br';
        sub_filter_once off;
        sub_filter_types text/html text/javascript application/javascript application/json;

        proxy_connect_timeout 60s;
        proxy_read_timeout 60s;
    }
}
```

## Por que cada ajuste resolve o problema

* X-Forwarded-Host e X-Forwarded-Port: Informam ao framework da sua aplicação qual é o endereço completo com a porta externa (2096). Muitos frameworks ignoram o Host padrão e leem esses dois cabeçalhos.
* proxy_redirect: Intercepta o cabeçalho Location quando a aplicação faz um redirect (como após um login) e injeta o :2096 antes de entregar ao navegador.
* sub_filter: Varre o código-fonte devolvido pela aplicação e substitui URLs absolutas que vieram sem porta. O Accept-Encoding "" é obrigatório aqui para o backend não enviar a resposta compactada em Gzip (o que impediria o Nginx de ler e substituir o texto).

## Passos para aplicar e testar

1. Salve o arquivo e teste a sintaxe do Nginx:bash
sudo nginx -t
```
2. Recarregue o serviço:bash
sudo systemctl reload nginx
```
3. Limpe o cache do navegador (ou teste em uma aba anônima), pois redirecionamentos 301 anteriores sem a porta ficam salvos no cache local do navegador.
